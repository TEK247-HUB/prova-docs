The Prova API is organized around standard REST principles. It accepts JSON-encoded request bodies, returns JSON-encoded responses, and uses standard HTTP response codes, authentication, and verbs.

## Environments & Base URLs

| Environment | Base URL | Network | Purpose |
| :--- | :--- | :--- | :--- |
| **Sandbox / Pilot** | `https://pilot.getprova.trade/api/v1` | Arbitrum Sepolia | Integration testing, institutional validation, and testnet escrows |
| **Local Development** | `http://localhost:3000/api/v1` | Local Machine / Hardhat | Local testing with Docker / Node server |

All API endpoints are versioned under the `/api/v1` path prefix. Health checks are served at the site root (`/health` and `/health/ready`).

---

## Standard Request Headers

| Header | Description | Required |
| :--- | :--- | :--- |
| `Authorization` | Bearer token format: `Bearer <access_token>`. | Required for all authenticated routes. |
| `Content-Type` | Must be `application/json` for all POST and PATCH requests. | Required for requests with a payload. |
| `x-encryption-mode` | Set to `server` (default) or `client` when creating escrows. | Optional (used on `POST /escrows`). |

## Standard Response Headers & Tracing

Every response emitted by the Prova API includes the following observability headers:

```http
HTTP/1.1 200 OK
Content-Type: application/json
x-request-id: req_01j984bcd4e5f6a7...
Access-Control-Allow-Origin: *
Strict-Transport-Security: max-age=31536000
```

- **`x-request-id`:** Unique identifier generated for every inbound request. Always include this ID when reporting issues or inspecting server logs.

## Rate Limits

The API enforces token-bucket rate limits per client IP / user session:
- **General authenticated routes:** 300 requests per minute.
- **Authentication Nonce requests (`/auth/wallet/nonce`):** 20 requests per minute.
- **OAuth 2.0 Token Exchange (`/api-credentials/oauth/token`):** 30 requests per minute.
- **Webhooks (`/webhooks/*`):** 300 requests per minute.

When a limit is exceeded, the server returns `429 Too Many Requests` with a `Retry-After` header indicating how many seconds to wait.
