This guide walks you through connecting to the Prova Sandbox on Arbitrum Sepolia, obtaining an access token, and executing your first authenticated API requests.

## Prerequisites

- **Node.js:** v18.0.0 or later (Node.js 22 recommended).
- **Ethereum Wallet:** An EVM wallet (MetaMask, Viem, ethers.js, or ZeroDev smart account) configured for **Arbitrum Sepolia** (Chain ID: `421614`).
- **HTTP Client:** `curl`, TypeScript (`fetch` / `axios`), or Python (`httpx`).

## Environments & Base URLs

| Environment | Base URL | Network | Chain ID |
| :--- | :--- | :--- | :--- |
| **Sandbox / Pilot** | `https://pilot.getprova.trade/api/v1` | Arbitrum Sepolia | `421614` |
| **Local Development** | `http://localhost:3000/api/v1` | Local / Sepolia Fork | `421614` |

<Steps>
  <Step title="Request an authentication nonce">
    Interactive sessions use Sign-In with Ethereum ([SIWE / EIP-4361](https://eips.ethereum.org/EIPS/eip-4361)). Request a single-use nonce for your wallet address:

    ```bash
    curl -X POST https://pilot.getprova.trade/api/v1/auth/wallet/nonce \
      -H "Content-Type: application/json" \
      -d '{
        "wallet_address": "0x742d35Cc6634C0532925a3b844Bc454e4438f44e"
      }'
    ```

    **Expected response (`200 OK`):**
    ```json
    {
      "nonce": "c6a8f1e94b2d41a0bc39e128",
      "issued_at": "2026-10-20T18:00:00.000Z",
      "expires_at": "2026-10-20T18:05:00.000Z"
    }
    ```
  </Step>

  <Step title="Sign the SIWE message and verify">
    Format the EIP-4361 message using your nonce, sign it with your wallet's private key, and exchange the signature for a JWT access token:

    ```typescript
    import { SiweMessage } from 'siwe';
    import { createWalletClient, http } from 'viem';
    import { privateKeyToAccount } from 'viem/accounts';
    import { arbitrumSepolia } from 'viem/chains';

    const account = privateKeyToAccount(process.env.WALLET_PRIVATE_KEY as `0x${string}`);
    const wallet = createWalletClient({
      account,
      chain: arbitrumSepolia,
      transport: http(),
    });

    // 1. Prepare EIP-4361 message
    const siweMessage = new SiweMessage({
      domain: 'pilot.getprova.trade',
      address: account.address,
      statement: 'Sign in to Prova',
      uri: 'https://pilot.getprova.trade',
      version: '1',
      chainId: 421614,
      nonce: nonceFromStep1,
    });
    const preparedMessage = siweMessage.prepareMessage();

    // 2. Sign message
    const signature = await wallet.signMessage({ message: preparedMessage });

    // 3. Verify signature with Prova API
    const response = await fetch('https://pilot.getprova.trade/api/v1/auth/wallet/verify', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        wallet_address: account.address,
        message: preparedMessage,
        signature,
      }),
    });

    const tokens = await response.json();
    console.log('Access token:', tokens.access_token);
    ```

    **Expected response (`200 OK`):**
    ```json
    {
      "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
      "refresh_token": "rt_8f192b0c1e844a...",
      "token_type": "Bearer",
      "expires_in": 3600
    }
    ```
  </Step>

  <Step title="Alternative: Server-to-server OAuth 2.0 exchange">
    For backend daemons or automated integration pipelines, exchange your issued `client_id` and `client_secret` directly without interactive signatures:

    ```bash
    curl -X POST https://pilot.getprova.trade/api/v1/api-credentials/oauth/token \
      -H "Content-Type: application/json" \
      -d '{
        "grant_type": "client_credentials",
        "client_id": "client_01HXYZ...",
        "client_secret": "sec_987654..."
      }'
    ```

    **Expected response (`200 OK`):**
    ```json
    {
      "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
      "token_type": "Bearer",
      "expires_in": 3600
    }
    ```
  </Step>

  <Step title="Query current user profile">
    Test your bearer token by fetching the authenticated user context:

    ```bash
    curl https://pilot.getprova.trade/api/v1/users/me \
      -H "Authorization: Bearer $ACCESS_TOKEN"
    ```

    **Expected response (`200 OK`):**
    ```json
    {
      "id": "usr_991823ab-cd45-4ef6",
      "wallet_address": "0x742d35Cc6634C0532925a3b844Bc454e4438f44e",
      "wallet_provider": "viem",
      "email": null,
      "created_at": "2026-10-20T18:01:00.000Z"
    }
    ```
  </Step>

  <Step title="Inspect confidential credit score for a buyer">
    Check the 4-signal credit score and FHE risk proof for a buyer counterparty:

    ```bash
    curl https://pilot.getprova.trade/api/v1/credit-score/0x1111111254fb6c44bac0bed2854e76f90643097d \
      -H "Authorization: Bearer $ACCESS_TOKEN"
    ```

    **Expected response (`200 OK`):**
    ```json
    {
      "buyer_address": "0x1111111254fb6c44bac0bed2854e76f90643097d",
      "raw_score": 740,
      "risk_proof": "0x04000000000002e4...",
      "expires_at": 1792518900
    }
    ```
    <Note type="info">
      Risk proofs have a 15-minute time-to-live (`expires_at`). If an unrecorded buyer address is queried, Prova defaults to a neutral initial score of `500`.
    </Note>
  </Step>
</Steps>

## Verifying your integration

To verify that your integration is properly wired:
1. **Correlation header:** Confirm that every API response includes the `x-request-id` header.
2. **Token refresh:** When `401 Unauthorized` occurs, call `POST /api/v1/auth/tokens/refresh` with `{ "refresh_token": "..." }`. Verify that the previous refresh token is invalidated.
3. **Health checks:** Monitor system status at `GET https://pilot.getprova.trade/health` and `GET https://pilot.getprova.trade/health/ready`.

## Common setup failures

| Symptom | Probable Cause | Diagnostic & Fix |
| :--- | :--- | :--- |
| `401 Invalid signature` | Nonce expired (5m TTL) or mismatched chain ID | Ensure your SIWE message uses `chainId: 421614` and matches the exact nonce issued by `/auth/wallet/nonce`. |
| `401 Missing authorization` | Missing `Authorization: Bearer <token>` | Pass the bearer token in the standard HTTP header. Ensure no extra quotes or prefixes exist. |
| `400 Invalid buyer address` | Malformed Ethereum address | Ensure the address is a 42-character hexadecimal string beginning with `0x` matching `/^0x[a-fA-F0-9]{40}$/`. |
| `429 Too Many Requests` | Exceeded route rate limit | Inspect `Retry-After` header and implement exponential backoff. Nonce requests are limited to 20/min. |
